# Native frozen-history report adapter

`internal/historyreports` computes the active CPAMP **Profile Workspace / Compare,
daily history and quota-window evidence** views natively from Pacer-owned history.
It ports the calculation dependency closure from `pacer-valuation` at
`e8492c245bf69144afdcf20b8b4ea8935f0476e5` (including `f94fedf`). It does not use a
running CPAMP process, proxy, collector or provider client.

## Proven parity and exact scope

The test oracle executes the **original CPAMP service and HTTP controller code**
using Go overlays in its checkout. The synthetic source contains five accounts,
five profiles (including overlapping/dated memberships), 41 events with a
40-event report checkpoint, 18 observations, canonical/contradictory closure
records, a historical policy, retained v2/v3 books, token enrichment and key
replacement lineage. Test outputs are generated by the original implementation,
not by this adapter.

Seven pinned scenarios and 30 window proofs match original JSON field/value
bytes. **81 complete controller JSON/CSV responses match byte-for-byte**, covering
daily/comparison/evidence exports, including their pins, category counters,
version strings, policy wording, missing/invalid statuses and provenance.
The v2 evidence-pin case retains kind/period/basis/scenario/gateway fields too.
Cold/warm `cache` envelope behavior is reproduced by a real bounded cache.

Independent numerical/behavioral assertions additionally verify:

- 250k observed 5m + 750k observed 1h = **$7.25**, with no assumptions;
- the same unknown request is unresolved in its pre-cutoff 5h window and assumed
  5m in its whole crossing week;
- 250k observed 5m + 500k observed 1h + 250k assumed 5m = **$6.50** at H exactly;
- a request recorded after H remains unresolved; events beyond the event
  checkpoint never enter totals;
- actual source-backed early reset changes v3 attribution, while an old v2 pin
  retains the original superseded/scheduled-window semantics;
- current, conflicting-closure and H-uncertain windows receive no assumed writes;
- allocation uncertainty keeps lower/upper bounds despite resolved TTL costs;
- missing prices, invalid counters, no-quota history, dated memberships,
  selected-key contributions and fixed 25-row request pagination survive.

This closes the **tested active-view calculation/export extraction gate**, not
every CPAMP view or the retirement gate. See the explicit exclusions below.

## Native ownership and preparation

Runtime dependencies are the existing SQLite driver, Go standard library and
local Pacer packages. Copied code lives under `internal/historyreports/internal/cpamp`;
the Go `internal` boundary keeps the reduced library behind this adapter.
Approximately 128 source declarations plus price/alias readers and pure CSV
writers preserve the original arithmetic/JSON layouts. Copying this dependency
closure avoids reimplementing subtly coupled valuation, meter allocation and
proof calculations. No CPAMP app/store/collector/polling/HTTP package is linked.
MIT notices and exact source hashes are in `cpamp/LICENSE` and `PROVENANCE.json`.

```go
archive, err := history.Open(trustedArchivePath)
// Explicit offline work, after archive.Import has fully published:
reports, err := historyreports.Prepare(ctx, archive, trustedScratchDirectory,
    historyreports.PrepareOptions{PollIntervalSeconds: 300})
preparedPath := reports.ArtifactPath() // trusted configuration, not an API DTO
defer reports.Close()

// Subsequent process/restart: metadata-only open, no rebuilding or source access.
reports, err = historyreports.Open(ctx, preparedPath)
```

`Prepare` creates its own directory beneath the supplied existing directory.
`history.Store.MaterializeReports` copies only required report tables in 250-row
transactions, preserving original rowids/checkpoints and checking each archived
row chain/count. It executes **compiled schema only**; source SQL, triggers and
virtual-table definitions are never executed. Settings, raw request/failure
bodies and unused source tables are not materialized. The complete private
archive remains untouched. Extra source columns irrelevant to this extracted
library remain archived, rather than being interpreted as calculation inputs.

Preparation calls the copied `PinHistoricalValuation` with the archive's explicit
checkpoint hash, event/observation cursors and H. It only derives completion from
the retained provider observations/canonical closure evidence. Then it creates
the new v3 comparison book. Existing retained books and profile revisions remain
unchanged in the disposable view. New-book capture time is **H**, replacing the
original wall clock; this deterministic preparation difference does not rewrite
an existing book's capture time or ID. Reads always use an explicit saved rule.
If H precedes the cutoff, the new book has no assumed-write cohort, even if the
source retained a later active cohort; all saved books/cohort rows still survive.

The SQLite view is closed, changed to `0400`, and reopened with
`mode=ro&immutable=1&_query_only=1`. It is a disposable native calculation artifact,
not a shared writable CPAMP database. Reads continue after the archive handle is
closed and CPAMP is absent. Keep its directory to retain paging cursors across
restart; remove that owned directory to discard it, then prepare again from the
published archive. Preparation failure cleans its newly created directory.

The source's optional `ANALYTICS_POLL_INTERVAL_SECONDS` affects credential
freshness status even in old pinned reports. Pass that captured setting explicitly
if nondefault. Zero/default means 300 seconds; accepted range is 60–86400. It is
stored with the preparation. There is no provider polling or environment lookup.
Other mutable metadata is the frozen archive's state: unavailable older alias or
inventory snapshots cannot be reconstructed from a report pin alone.

Preparation and first aggregate computation scale with retained history and must
run outside routing/startup critical paths. Explicit ceilings are 500,000 events,
100,000 observations, 1,000 accounts, 10,000 profile revisions and 1,000 latest
profiles. Oversize input fails instead of returning truncated totals. No expensive
work is hidden in `Open`. New report calls carry a cooperative 30-second context
deadline; the inherited pure calculations are not a hard-preemptible worker.
Fixed filters share a 16-entry immutable-report cache; pages read their own
25-row request slice. Cache DTOs are cloned, not shared mutable slices/maps.

## Parent API contract

Parent owns authorization, HTTP limits, `internal/pacer` handlers and UI. All
these methods are authenticated-independent domain APIs; require management auth
before calling them. Paths/`Prepare`/materialization are trusted offline
capabilities and must never be exposed through a management request.

```go
Profiles(ctx, revision int64) (ProfileList, error)
Report(ctx, Query) (Workspace, error)
ListWindows(ctx, WindowQuery) (WindowPage, error)
Evidence(ctx, Query, windowID string) (Evidence, error)
ExportJSON(ctx, Query, ExportOptions, io.Writer) error
ExportCSV(ctx, Query, ExportOptions, io.Writer) error
```

These are methods on `*historyreports.Reader`. `DefaultPin()` returns the
H/checkpoint-anchored starting pin. `Workspace`, `Window`, `Evidence`, `Pin` and
`EvidencePin` retain the source JSON schemas; calculations/version labels are
the original CPAMP values, not new approximations.

### Profiles and filters

- `Profiles(-1)` selects the latest frozen revision; `Profiles(0)` selects initial
  revision zero. Results retain source profile IDs/membership dates and add
  `reference="profile:"+SHA256(sourceProfileID)`, matching `history.Store.Profiles`.
- A new `Query` accepts `ProfileReference` (or `all`/`unassigned`),
  `AccountReference="account:"+SHA256(sourceAccountID)`, `KeyHashes`, `Model`,
  `From`, `To`, and `RequestPage`. Empty filters mean the complete frozen selection.
  Dates retain CPAMP's half-open request/overlapping-whole-window semantics.
- `Query{Pin: &savedWorkspaceFilter}` replays an old report exactly. Mixing a pin
  with native filter overrides is rejected. For another request page, copy the
  pin and change only `Page`. Revision zero and estimator omission retain their
  original initial-revision/v2 meanings; valuation rule is mandatory.
- `Query{EvidencePin: &savedQuotaUsageFilter}` replays a complete old window pin,
  including period, kind, basis and scenario metadata. Other query fields must
  be empty. `Evidence` can receive an empty window ID or the same ID as the pin;
  contradictory IDs are rejected. Report/list operations reject evidence pins.
- Pins cannot exceed archive event/observation bounds, frozen token/forecast
  revisions, or H (`at`). Retained historical books whose embedded cohort exceeds that
  archive boundary are rejected. No pin silently advances a cursor or policy.
- Native key lists allow at most 100 SHA256 hashes; model names are at most 256
  bytes, request pages 0–1,000,000. Full legacy key selectors are also validated.
  There is no raw-key argument. Quota remains a shared provider denominator.

Default reports use the frozen source profile/alias metadata. Parent may display
current native key aliases as a separate UI label; do not splice mutable labels
or display groups into pinned calculation/export DTOs. The report DTOs retain
CPAMP's credential identity/label/auth-filename metadata and allowlisted evidence;
they are management-private, not inference-key usage endpoints. No raw CPA keys,
`settings`, `usage_events.raw_json` or `fail_body` enter report calculations.

### Completed-window pagination

`WindowQuery` embeds `Query`, with `Kind` (`5h`, `weekly`, or empty), `State`
(`completed` default, `current`, `all`), `Limit` (default 25, maximum 100) and
`Cursor`. Choose one profile or the global selection; `all`-profiles is rejected
here because overlapping membership contributions cannot be merged implicitly.

Rows preserve CPAMP ordering: scheduled reset descending, then window ID ascending.
V3 completed pages require closed canonical completion with its latest bound no
later than the report's At; ambiguous/current/H-crossing completions stay available
under `all`. Early closures preserve scheduled reset ordering and expose actual
attribution end/provenance. V2 pages retain legacy recorded closed-status semantics.

The page returns the full pin, exact matched total, windows and a signed cursor.
The cursor binds preparation, source snapshot, full filters, state/kind, page size
and last row. Tampering, another preparation or changing a filter/limit fails
with `ErrCursor`; it is not authorization. Cursors survive reopening the same
artifact, not rebuilding a new one. Native edits cannot move frozen pages.

### Exports

- `ExportJSON(..., ExportOptions{}, w)` produces the workspace object.
- `ExportCSV` requires `CSV: "daily"` or `"comparisons"`. Comparison options
  `Kind` and `ProfileReferences` select rows (maximum 100 refs). They do not change
  calculations or alter saved report pins.
- `ExportOptions{WindowID: id}` or `Query.EvidencePin` selects quota evidence for
  either format. Selected/shared/boundary evidence overlaps; it is not additive
  spend. CSV preserves source column order and formula-cell escaping.

Suggested error mapping: `ErrInput`/`ErrBoundary` -> 400, `ErrCursor` -> 409,
`ErrSource` -> 503; context cancellation/deadline follows parent conventions.
`ErrLimit` is an explicit offline preparation limit. Source/driver strings and
paths are not returned in domain errors. Stream writer failures are returned.

## Reproducing the oracle and extraction

Use the task-local Go caches from the implementation receipts. No command below
opens a live database or edits the analytics checkout:

```sh
go run internal/historyreports/generate/extract.go /path/to/analytics
python3 internal/historyreports/generate/oracle.py /path/to/analytics /fresh/task-local/output
python3 internal/historyreports/generate/pack.py /fresh/task-local/output
go test -race -tags sqlite_fts5 ./internal/history ./internal/historyreports/...
```

`oracle.py` overlays two test files into original service/controller packages,
creates a fresh synthetic SQLite database, calls the original methods/handlers,
and records source commit plus output hashes. `pack.py` checks those hashes and
stores deterministic gzip goldens; no SQLite file is committed. Regular tests
restore that source SQL into a frozen synthetic DB, use the real Pacer archival
import and report materializer, then compare native computation with the original
outputs. Tests also cover corrupt-chain rejection, no archived-trigger execution,
readonly/independent reopen, private raw-field exclusion, cache ownership,
concurrent reads, cancellation, reference validation and signed paging.
An additional case removes all v3 books/cohorts before import: native preparation
recomputes the same original report from retained observations/prices, without
rewriting the archive or reading a stored report result.

The implementation receipts also retain the original full synthetic CPAMP SQLite
snapshot (with FTS), its frozen manifest, a completed native archive, and a prepared
read-only artifact. Native replay on that actual snapshot passes the same seven
workspaces, 30 proofs and 81 bytewise exports under the race detector. Parent can
reuse it for authenticated UI/lab acceptance; this check does not exercise HTTP.

## Remaining gates and intentionally unported views

- Legacy `ProfileReport`/`ProfileProof`, legacy exhaustion/forecast UI, and the
  separate `QuotaUsage` subscription-tier scenario listing/export are not ported.
  Retaining their input tables does not establish those views' report parity.
- Live overview/background-refresh behavior, provider refresh/manual quota edits,
  native profile mutations and integration of future measurement-store events are
  outside this frozen-read adapter. No live observer/queue consumer was added.
- The oracle is representative synthetic Claude history. Real approved frozen
  production-data parity, larger-report performance, all-provider acceptance,
  unavailable historical metadata, migration/cutover and real restore/rollback
  still need validation. External report-artifact inventory/UI wiring remains
  parent work; the adapter accepts their typed pins and does not proxy stored
  report outputs as newly computed results.
- Parent HTTP authorization and CPA/CPAMP real-browser navigation, including
  CPAMP-unavailable operation, remain unverified here. No production access,
  deployment, remote push or CPAMP retirement was performed.
